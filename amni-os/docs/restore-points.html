RESTORE POINTS

Updated 25 Sep 2026

On Btrfs, which the installer uses by default, Amni OS takes a restore point before and after every package change, plus a rolling set by the hour and day. If an update breaks something, you can boot the machine as it was and then undo the change.

What gets saved

WhenKept
Before and after every install, update or removal (snap-pac)10 pairs, 5 of them marked important
Every hour (snapper timeline)5 hourly, 7 daily, 2 monthly
When restore points were switched onOne “Restore points enabled” snapshot

Snapshots cover the system (the @ subvolume). Your files in /home live on their own subvolume and are not rolled back, so going back never loses your documents. It also means they are not a backup: keep a copy of anything important somewhere else.

Snapshots share unchanged data, so they take little space. Old ones are removed as new ones arrive.

Take one now

Before you try something risky, open Amni Control and take a restore point from the Restore points card. From a terminal:

sudo snapper -c root create -d "Before trying the new driver"

To see the list:

sudo snapper -c root list

Boot an older state

  1. Restart and hold Shift (BIOS) or press Esc (UEFI) if the boot menu does not show.
  2. Open the Arch Linux snapshots submenu. That is grub-btrfs's name for it.
  3. Pick a snapshot by date and description, then a kernel.

A snapshot boots read-only with a temporary layer in memory on top. You can log in, open apps and check whether the problem is gone, but nothing you do there is kept. Restart to return to the normal system.

Undo a bad update

Once you know which update caused the problem, undo it from the normal system. Every update has a pre and post snapshot; find the pair in snapper list (the description shows the pacman command), then check what it changed and revert it:

sudo snapper -c root status 41..42
sudo snapper -c root undochange 41..42

Replace 41..42 with your pre and post numbers, then reboot. undochange restores the files the update touched, including pacman's own database, so the package list matches again.

If the normal system will not boot at all, try the Amni OS (LTS kernel) entry first, then safe graphics. If nothing gets you to a desktop, ask on Haven and we will walk through it with you.

On ext4 or XFS

Snapper needs Btrfs. On an ext4 install, Timeshift takes a restore point before every pacman transaction. Open Timeshift from the menu to browse and restore them.

Check that it works

amni-bug-info has a Restore points section: the Snapper version, whether the root config exists, the snapshot count (with sudo) and whether the timers are enabled.
