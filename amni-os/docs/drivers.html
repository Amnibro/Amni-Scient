Amni OS installs the drivers your machine needs and nothing else. Two pieces do it: amni-gpu-apply for the display, and amni-driver-apply for everything else. Both use packages from the Arch repositories and the Amni repository. Nothing about your hardware leaves the machine.

Graphics

amni-gpu-apply runs at install and from Amni Control's GPU drivers button. It reads the PCI IDs of your display devices and picks a stack:

CardDriver
AMD, IntelMesa (open source, in the kernel)
NVIDIA GTX 16xx, RTX 20xx and newernvidia-open, loaded early so the boot splash and login screen keep the display
Older NVIDIAnouveau, plus NVK Vulkan through a driver rule
VirtualBox, VMware, QEMUThe matching guest graphics path

The result is written to /var/lib/amni-os/gpu.json. If a boot fails to reach the desktop, the next boot uses safe graphics automatically (NVIDIA first gets one retry on nouveau). See troubleshooting.

Everything else

amni-driver-apply collects facts about the machine, matches them against the rules in drivers.json, and installs the packages of every rule that matches. It runs:

  • when a USB device is plugged in, or a Bluetooth input device pairs,
  • after amni-gpu-apply,
  • 4 minutes after boot and then daily, to retry anything that failed while offline.

It never runs in the live session, waits for the package manager if it is busy, and never refreshes the package database on its own (no partial upgrades). It shows a notification naming what it installed and writes its result to /var/lib/amni-os/drivers.json.

Required and optional

Required rules install their packages, enable their services and add users to the groups they need. Optional rules (Razer and Logitech tools, NVMe tools, OpenCL, Intel NPU) are only listed until you install them from Amni Control's Optional device tools.

What the rules cover

  • Graphics: Intel and NVIDIA video decoding, hybrid-GPU switching and prime-run on laptops, NVK for older NVIDIA
  • Laptops: thermald on Intel laptops, fingerprint readers
  • Wireless and phones: Bluetooth file transfer, iPhone and iPad, USB modems
  • Printing: driverless USB printing, plus HP, Brother, Samsung and Epson drivers
  • Gaming: Xbox controllers over Bluetooth and the Xbox Wireless Adapter
  • Docks: DisplayLink
  • Virtual machines: QEMU, VirtualBox, VMware and Hyper-V guest tools
  • Vendor tools: ASUS laptop controls and GPU modes, Framework tools

How a rule reads

{"id":"intel-thermal","name":"Intel laptop thermal control",
 "when":["cpu:intel&laptop"],"pkgs":["thermald"],"services":["thermald.service"]}
FieldMeaning
whenA list of alternatives. Any one matching is enough; & joins facts that must all match. * is a wildcard.
pkgsPackages to install
servicessystemd units to enable once the packages are in
groupsGroups to add every user account to
tierrequired (default) or optional

FactExample

See what matched on your machine

/usr/lib/amni-os/driver-apply --dry-run

This prints the matched rules, what would be installed and the facts it found, and changes nothing. amni-bug-info shows the last real run.

To change the rules on one machine, copy them to /etc/amni-os/drivers.json and edit that copy; it takes priority over the packaged file.

Hardware that is not covered

Open a hardware or driver request with the output of lspci -nn and lsusb. Those IDs are what a new rule matches on.
