Start here when something is off. If none of this helps, run amni-bug-info and bring its output to support.

Black screen or frozen logo at boot

  • From the USB: choose Amni OS live (safe graphics) in the boot menu.
  • Installed: Amni OS notices a boot that never reached the desktop and starts the next one in safe graphics by itself. Just restart. Once you are logged in, Amni Control's Home says so and offers Use full graphics.
  • NVIDIA: after a failed boot, Amni OS first retries once on the open nouveau driver. Run GPU drivers in Amni Control to set the right driver up again.

“Verification failed” or a Secure Boot violation

The machine's key was not enrolled. Turn Secure Boot off, boot Amni OS, run sudo /usr/lib/amni-os/secureboot-setup, and reboot: MokManager appears, choose Enroll MOK and use the password amnios. Then turn Secure Boot back on. Details are in the install guide.

No Wi-Fi, or it drops after sleep

Use Wi-Fi fix in Amni Control. It wakes the adapter back up and reconnects to your saved networks. Broadcom cards get the wl driver automatically when one is detected. If the adapter is not listed at all, send us its line from lspci -nn or lsusb in a hardware request.

An update failed or never arrives

  • Automatic updates run 10 minutes after boot and then daily. They skip quietly when the network or the package manager is busy.
  • See the last runs: journalctl -u amni-update --no-pager | tail -30
  • By default only Amni packages update on their own. Check updates in Amni Control (or Discover) applies everything else.
  • The setting is SCOPE in /etc/amni-os/update.conf: os (default), all, or off.

Something broke after an update

Boot the restore point from before the update, check the problem is gone, then undo the update. The restore points guide has the steps.

No sound

Images before 0.4.6.6 could ship without the PipeWire session manager. Updating amni-os-core repairs it. To fix it by hand:

systemctl --user enable --now pipewire.socket pipewire-pulse.socket wireplumber.service

Bluetooth devices do not show up

Turn Bluetooth on from Amni Control, then pair from the Bluetooth tray icon. Keyboards and mice need to be in pairing mode. If a controller pairs but does nothing, the driver rules install its driver shortly after pairing.

Amni Share or KDE Connect cannot see other devices

The firewall is on by default. Amni OS opens the KDE Connect ports for your local network only, and re-applies that on every update and whenever you flip the firewall switch in Amni Control. Both devices need to be on the same network.

Collecting details for a report

amni-bug-info
journalctl -b -p err --no-pager | tail -50

amni-bug-info leaves out your username, hostname, IP and MAC addresses and serial numbers. Logs can contain personal details, so read them before you post.
