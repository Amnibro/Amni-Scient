THE REFFELT CONSTANT

SPECTRAL FINGERPRINTING OF HIGH-DIMENSIONAL PARAMETER SPACES · VERSION 2

One digit per parameter, read off the low-eigenvalue modes of a graph built over evaluated configurations, so I can see which knobs are worth tuning. It ships with fixed math, published code and measured results.

ABSTRACT

Here's the problem. You've got a D-dimensional parameter space, a pile of evaluated configurations, and no clear idea which knobs the score actually cares about. The Reffelt Constant (ℜ) is my quick read on that: a digit string with one digit per parameter. I build a graph over the configurations, take the smooth, low-eigenvalue modes of its normalized Laplacian, and ask how those modes move along each parameter axis. A 0 says “this knob matters less than average, freeze it”. A 5 to 9 says it matters, on a doubling scale.

This is version 2. It replaces version 1's hand-picked, never-tested constants with fixed math, published code, and measurements on test functions with a known right answer. The short version: on an optimizer's winners, v2 ranks the knobs that matter above the ones that don't almost every time, and it beats the simple baselines I tried in most settings. On a plain random sample it needs its other reading and ends up level with those baselines, not ahead.

One word you'll run into further down: ground state. When I say it on this page, I mean the low-eigenvalue subspace of the Laplacian. It's an analogy to a physical ground state, and it stops there: there's no temperature and no partition function in the math.

Status, 2026-10-05. The graph, the normalized Laplacian and the eigensolver are standard spectral graph theory. The two readings of the modes and the digit scale are my construction, now written down and fixed (Steps 4 and 5). The code is published as reffelt_constant.py (NumPy only), and every number on this page comes from reffelt_results.json: 5 test functions, 10 to 50 parameters, two ways of sampling, 10 seeds each. On winners' archives, v2 separates the knobs that matter from the ones that don't with an AUC of 0.96 ± 0.03 across 15 settings; the best simple baseline, a binned first-order Sobol' index, gets 0.90 ± 0.13. On random samples v2 gets 0.79 ± 0.09, level with the baselines, and wins only 1 setting out of 15. All of it is synthetic. Not measured yet: real archives (the original optimizer outputs aren't on disk) and the application ideas at the bottom.

WHAT CHANGED FROM V1

What moved, for comparison with the previous version:

  • The old weight measured roughness. v1 averaged |Δψ| along each coordinate's sort order. That's a roughness: it's big when a mode ignores the coordinate. The old page described the opposite. On random samples, v1 ranked the important knobs below the unimportant ones (AUC 0.26 ± 0.08, worse than a coin). On winners' archives it worked (0.82 ± 0.11), for a specific reason: among winners, the smooth modes run along the knobs the winners are free to vary, so roughness marks the knobs that are pinned. v2 keeps that reading on purpose, names it, and adds the other one for random samples.
  • Eigensolver. v1 took the smallest singular values with scipy's svds and kept the zero mode. v2 takes the smallest eigenpairs of Lnorm (dense eigh up to 3,000 points, shift-invert Lanczos above that) and skips one zero mode per connected component.
  • Basis. When several eigenvalues are nearly equal, the individual eigenvectors aren't well defined; only the space they span is. v2 measures steps in the whole 16-mode embedding with a Euclidean norm, which doesn't change under rotations inside that space. A per-mode statistic fails here: an early draft that averaged one changed its digits between two eigensolvers on the same data.
  • Pairing. Gone. v1 paired mode j with dimension j. v2 prints one digit per parameter, in parameter order.
  • Scale. The 800 and the 0.01 and 1.0 thresholds are gone. A digit is now log2 of the weight relative to the uniform weight 1/D, so it means the same thing in any D.

CORE DERIVATION

STEP 1 — SCORE-WEIGHTED GRAPH CONSTRUCTION

I start with N evaluated parameter vectors pi ∈ ℝD and their scores si, higher is better. First I rescale every coordinate to [0,1] with its min and max over the archive, so d(pi,pj) is a plain Euclidean distance and ε has no units. Then I build a k-nearest-neighbor graph, k = 32, and weight each edge by distance and by score similarity:

EQUATION R1 — GRAPH WEIGHT
$$w_{ij} = \frac{\exp\left(-\frac{|s_i - s_j|}{\sigma_s}\right)}{d(p_i, p_j) + \epsilon}$$

σs is the standard deviation of the scores, and ε = 0.1. An edge exists if either point is among the other's 32 nearest neighbors, which keeps the matrix symmetric. Two points that sit close together and score about the same get a heavy edge. Measured: on winners' archives the score term doesn't help. With every edge weight set to 1, v2 scored 0.98 ± 0.03 instead of 0.96 ± 0.03. The selection that made the archive already did the work. I've kept R1 as written so the construction stays the one I describe, and the unit-weight run is in the JSON.

STEP 2 — NORMALIZED GRAPH LAPLACIAN

This step is standard; see Chung, Spectral Graph Theory (1997) and von Luxburg, “A tutorial on spectral clustering,” Stat. Comput. 17 (2007). From the adjacency matrix A with weights wij and degree matrix D = diag(Σjwij):

EQUATION R2 — NORMALIZED LAPLACIAN
$$L_{\text{norm}} = I - D^{-1/2} A D^{-1/2}$$

The eigenvalues lie in [0, 2]. Small eigenvalues belong to modes that vary slowly across the graph: that's the global structure I'm after. Large eigenvalues belong to modes that flip sign between neighbors: local noise.

STEP 3 — SPECTRAL EMBEDDING

I keep the m = 16 smallest nonzero eigenpairs, skipping one zero eigenvalue for each connected piece of the graph. Up to 3,000 points that's a dense symmetric eigensolver; above that, shift-invert Lanczos just below zero. Each configuration then gets a point in a 16-dimensional embedding, using the random-walk form of the eigenvectors (Belkin & Niyogi 2003):

EQUATION R3 — EMBEDDING
$$L_{\text{norm}} \psi_j = \lambda_j \psi_j, \quad 0 < \lambda_1 \le \cdots \le \lambda_{16}, \qquad f_j = D^{-1/2}\psi_j, \qquad F_i = \big(f_1(i), \ldots, f_{16}(i)\big)$$

STEP 4 — TWO READINGS OF THE SAME MODES

v1 blended this step; v2 splits it. The smooth modes mean different things depending on where the archive came from, so v2 asks you which kind you have.

Winners' archive (the default). This is what an optimizer hands you: the top configurations of a search. Sort the archive by coordinate d, walk along that order, and measure how far each step moves in the embedding. Compare that with the average distance between two random configurations. I call the result the freedom of dimension d:

EQUATION R4 — FREEDOM (WINNERS' READING)
$$M_d = 1 - \frac{\frac{1}{N-1}\sum_{i=1}^{N-1}\lVert F_{\pi_d(i+1)} - F_{\pi_d(i)} \rVert}{\frac{1}{N(N-1)}\sum_{a \ne b}\lVert F_a - F_b \rVert}, \qquad w_d \propto \frac{1}{\max(M_d, \sigma_0)}$$

πd sorts the archive by coordinate d. This is v1's finite difference along the sort order, with the norm taken across all 16 modes at once and divided by its value for a random order. Md near 0 means the embedding jumps around as d changes: the winners are pinned along d, so d matters. Md well above 0 means the embedding moves smoothly with d: the winners roam freely along d, so it doesn't matter much. σ0 is the spread of Md under a random order (the standard deviation of the pair distances, over their mean, over √(N−1)), so a freedom below the noise floor counts as the noise floor.

Unbiased sample. If the archive is a random or space-filling sample, its geometry says nothing; only the score does. So I smooth the score on the graph by projecting it onto the 16 modes, and measure how much the smoothed score depends on each coordinate with Chatterjee's rank correlation ξ (JASA 116, 2021):

EQUATION R4′ — DEPENDENCE (UNBIASED READING)
$$\hat s = \sum_{j=1}^{16} c_j f_j,\quad c_j = \psi_j^{\top} D^{1/2}(s - \bar s_D), \qquad \xi_d = 1 - \frac{N\sum_{i=1}^{N-1}\left|r_{\pi_d(i+1)} - r_{\pi_d(i)}\right|}{2\sum_{i=1}^{N} l_i (N - l_i)}, \qquad w_d \propto \max(\xi_d, 0)$$

ri counts the points with ŝ ≤ ŝi, li counts the points with ŝ ≥ ŝi, and ŝD is the degree-weighted mean score. It's the same sorted finite difference again, on ranks: 0 means no relation, 1 means the smoothed score is a function of xd. The projection uses the whole 16-mode space, so it doesn't care how the solver picked the basis inside it.

Pick the wrong reading and the ranking flips. The winners' reading on random samples scored 0.27 ± 0.08; the unbiased reading on winners scored 0.52 ± 0.13. That's the biggest practical caveat on this page.

STEP 5 — DIGIT ENCODING

Last step! The weights sum to one, so the uniform weight is 1/D. I compare each weight with that and print the comparison on a doubling scale:

EQUATION R5 — THE REFFELT CONSTANT, V2
$$r_d = D\,w_d, \qquad \Re_d = \begin{cases} 0, & r_d < 1 \\ \min\left(9,\; 5 + \lfloor \log_2 r_d \rfloor\right), & r_d \ge 1 \end{cases}$$

In code: r = D * w; digit = 0 if r < 1 else min(9, 5 + floor(log2(r))). Why 0 for anything below average? A significance test, tried first on the development seeds, froze about half of the knobs that mattered. “Below average” is scale-free, needs no tuning, and kept 0.89 of the active knobs while freezing 0.90 of the distractors on winners' archives. Its catch: it always freezes something, even when every knob matters equally.

READING THE DIGITS

DIGITWEIGHT VS AVERAGE (1/D)WHAT I DO

74× to 8×Tune first
88× to 16×Tune first

Digits 1 to 4 don't appear, because anything below average prints 0. v1's “valid when there's no 0 and no 9” rule is retired: in v2 a 0 is an answer, not an error, and a 9 is just a knob that carries a lot of the weight. How steady are the digits? I drew a second archive from the same problem with a different seed and compared the strings position by position. On winners' archives 75% of the digits matched, and the average change was about one digit. Most of the flips are between 0 and 5, right at the average line. Read single digits near that line loosely.

OUTPUT STRUCTURE

Here's the record reffelt() returns:

RESULT SCHEMA
constant:        str          ← the ℜ string, one digit per parameter (e.g. "0050560500")
reading:         str          ← "elite" (winners) or "unbiased" (random sample)
causal_weights:  List[float]  ← w_d, D entries, sum = 1
freedom / xi:    List[float]  ← M_d (elite) or ξ_d (unbiased)
keep:            List[bool]   ← digit ≠ 0
eigenvalues:     List[float]  ← the 16 smallest nonzero λ_j
mode_energy:     List[float]  ← share of the score's smooth part in each mode
lowpass_r2:      float        ← how much of the score the 16 modes carry
zero_modes:      int          ← connected components skipped

The v1 fields for frozen values, compression ratio and walk-forward degradation are gone from the core. Freezing at best-seen values is one line on top of keep, and walk-forward is still unmeasured.

WHAT I MEASURED

I needed problems where I know the right answer, so I used synthetic ones. Five test functions, each hiding a few active parameters at random positions among 10, 20 or 50: an additive mix (5 active, including two non-monotone terms), the Sobol' G-function (4 active), Ishigami (3 active, with one that only acts through an interaction), a pure interaction with zero main effects (4 active), and a ridge along a random direction inside 4 active dimensions. Noise is 20% of the function's standard deviation, plus one 100% run at D = 20. Ground truth is the total-effect Sobol' index from 4,096 Monte Carlo samples per parameter.

Two ways to fill the archive, 512 configurations each. Winners: a simple evolution strategy runs for 2,176 evaluations and I keep the top 512, which is what an optimizer leaves behind. Random: 512 uniform samples. Each setting gets 10 seeds (0 to 9); I designed v2 on seeds 1000 to 1003 and didn't use those here.

Baselines: |Spearman| of each parameter with the score; Chatterjee's ξ of each parameter with the raw score; a binned first-order Sobol' index (16 quantile bins, the given-data estimate of Var E[s|xd] / Var s); and permutation importance from a k-nearest-neighbor regressor. scikit-learn isn't installed on this machine, so random forest and fANOVA aren't in the comparison. The main score is AUC: the chance a randomly picked active parameter outranks a randomly picked distractor. 0.5 is a coin flip, 1 is perfect.

Where v2 wins. Winners' archives. It beat every baseline outright in 9 of 15 settings and was within 0.02 of the best in 14 of 15. Its worst setting was 0.90; every baseline dropped below 0.70 somewhere. The clearest gap is the ridge, where the active parameters only matter in combination: v2 scored 0.90 to 0.96, the best baseline (|Spearman|) 0.79 to 0.88, and the binned Sobol' index 0.63 to 0.70. At 100% noise v2 still beat the best baseline on three of the five functions (additive 0.85 vs 0.68, Ishigami 0.95 vs 0.89, ridge 0.85 vs 0.58).

Where it loses. On winners' archives, the binned Sobol' index edged it out in the other 6 settings, by 0.002 to 0.025: the G-function at D = 10 and 50, Ishigami at all three sizes, and the pure interaction at D = 50. At 100% noise it also won on the G-function (0.84 vs 0.78) and the pure interaction (0.82 vs 0.78). On random samples v2 is a fair method and nothing more: 0.79 against 0.80 to 0.82 for ξ, the binned Sobol' index and kNN permutation, and it won 1 setting of 15. If the archive is random, use the simplest baseline and save the eigensolver. The pure interaction on random samples is the sharpest loss: only kNN permutation found it (0.98 to 1.00 against v2's 0.60 to 0.73), because every rank method here looks at one parameter at a time.

Ranking inside the active set. The Spearman correlation between v2's weights and the true total-effect indices, over all D parameters, is only 0.47 ± 0.20 on winners. v2 separates active from inactive well; it's much weaker at ordering the active ones among themselves. Don't read 7 versus 6 as a reliable ranking.

LIMITS

Scope of the numbers above:

  • Everything is synthetic. No real-archive result yet: the BTC, ETH and SOL optimizer runs aren't on this machine.
  • The winners all came from one simple evolution strategy. CMA-ES, a genetic algorithm or TPE leave archives with different shapes, and the winners' reading depends on that shape. Untested.
  • You have to say which kind of archive you have. The wrong reading inverts the ranking, and v2 can't tell the two apart on its own.
  • The 0 rule is relative. It always freezes something, and about one digit in four changes between two archives from the same problem.
  • It finds which knobs matter, not their order: Spearman against the true indices is 0.47 on winners.
  • The score term in R1 didn't help on winners. I kept it for continuity; unit weights did as well or slightly better.
  • N = 512 throughout, and 16 modes. Neither is swept yet. Walk-forward stability, the original v1 promise, is still unmeasured.

HOW TO REPRODUCE

Run it yourself. Grab reffelt_constant.py; it needs only NumPy (SciPy is used above 3,000 points if it's there). Then:

COMMANDS
python3 reffelt_constant.py bench --seeds 10        # writes ../reffelt_results.json, about 5 minutes on 2 cores
python3 reffelt_constant.py run my_archive.csv       # winners' reading, last column is the score
python3 reffelt_constant.py run my_sample.csv --reading unbiased --v1

The benchmark is seeded end to end, so a rerun gives the same JSON apart from the date and the runtime. The JSON holds every setting's per-seed AUCs, the freeze and retest numbers, and one example string per setting next to its true active set. The older private implementation is retired; the --v1 flag reproduces its encoder so you can compare.

RELATED WORK

The graph and the embedding are the same objects as in Laplacian eigenmaps (Belkin & Niyogi, Neural Computation 15, 2003) and diffusion maps (Coifman & Lafon, Appl. Comput. Harmon. Anal. 21, 2006). Scoring each feature by how smooth it is on a graph goes back to the Laplacian score (He, Cai & Niyogi, NIPS 2005); I tried its linear form, and it failed on the G-function and the pure interaction, which is why R4 uses distances in the embedding instead. The ξ in R4′ is Chatterjee's coefficient (J. Amer. Statist. Assoc. 116, 2021). The ground truth is the total-effect Sobol' index with the Jansen estimator (Saltelli et al., Comput. Phys. Commun. 181, 2010), and the binned baseline is a given-data first-order estimate in the spirit of Plischke, Borgonovo & Smith (Eur. J. Oper. Res. 226, 2013). The winners' reading, that the near-optimal set stretches along unimportant directions and is pinned along important ones, is the same picture as parameter sloppiness (Gutenkunst et al., PLoS Comput. Biol. 3, 2007). For hyperparameter importance specifically, fANOVA (Hutter, Hoos & Leyton-Brown, ICML 2014) is the next comparison to run.

THINGS I'D LIKE TO TRY

Next tests. Only the first one has a number behind it, and it's the synthetic one above.

HYPERPARAMETER OPTIMIZATION

The basic one, and now the one with the best footing: the winners' reading works on an optimizer's own archive. The test I want: run a search, compute the constant, freeze the 0 digits at their best-seen values, spend the rest of the budget on the others, and count the evaluations saved against a search that never freezes. Not run yet.

A REAL ARCHIVE

Rebuild my trend-strategy optimizer's winner set, or any real tuning log with a known answer, and see whether the 0.96 survives contact with real archives. That's the result that would actually matter.

NEURAL ARCHITECTURE SEARCH

Same move, bigger space: compute the constant on a first sweep, freeze the 0 digits, and see whether the next sweep finds the same architectures with fewer evaluations. Not run yet.

TRAINING DIAGNOSTICS

Compute the constant at checkpoints across a set of training runs and watch which digits move. The Eigenstretch page does this for a running search on simulated data; on training runs it's untested.

WORKLOAD FINGERPRINTING AND DESCRIPTOR SCREENING

Two wide spaces where I'd like to see how many dimensions survive: per-node resource traces, and QSAR descriptor sets with binding affinity as the score. With one digit in four flipping between archives, the string isn't stable enough to use as a lookup key, so these would have to use the weights. No numbers yet.
