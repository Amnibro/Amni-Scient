UNIVERSAL GROUND STATE KERNEL

SVD OVER OPTIMIZER WINNERS

I ran an SVD over the winning parameter sets from my trading-bot optimizer. For one strategy family, two components explained 95.6% of the score-weighted variance: a volatility scale k and a trend/reversal switch. The other family didn't collapse. This page shows the method and what I found.

Status, 2026-09-09. The SVD method (G1 to G6) is derived on this page and matches universal_reffelt_meta_optimizer.py. The 95.6% figure is measured on the winner set my optimizer wrote out on Nov 30 2025 for a 15-parameter trend strategy on BTC, ETH and SOL 15-minute bars; the mean-reversion family came out about 7D. The three charts are illustrations with made-up numbers. The GP-plus-Thompson meta-optimizer is a plan, the applications are conjecture, and the digit encoding in G7 disagrees with the code.

ABSTRACT

The Universal Ground State Kernel is what I named the finding that the winning configurations from my optimizer weren't spread through the full parameter space. For one family they sat on a two-dimensional manifold: a continuous scaling factor k ∈ [0.3, 3.5] and a regime bit ∈ {0, 1}.

The one clean case was a 15-parameter trend strategy on BTC, ETH and SOL 15-minute bars. Two singular values carried 95.6%. The mean-reversion family was about 7D, with the regime bit as its main axis. I don't have evidence this holds outside my own optimizer. The method is an SVD of a score-weighted parameter matrix, plus a loading analysis to sort parameters into ones that move the top components and ones I can freeze. On the clean case that takes 15 parameters to 2 components.

Data: strategy family AMR/AGS (trend-following) and ANC (mean-reversion); tickers BTC/USD, ETH/USD, SOL/USD; 15-minute bars; the elite set is the winner list my optimizer saved (I haven't published the count); run date Nov 30 2025. The script header credits Anthony Reffelt with Grok 4.1 assistance.

THE GROUND STATE
$$\mathcal{G} = \{(k, \; \text{regime}) \;:\; k \in [0.3, 3.5], \;\text{regime} \in \{0, 1\}\}$$

In the trend family, every other parameter is frozen at a constant from the analysis: the score-weighted median of the winners, with weights si. I haven't run a perturbation test on the frozen values, so "insensitive" is a guess until I do.

DERIVATION

STEP G1 — UNIFIED PARAMETER VECTOR

Collect all configurations into a standardized N-dimensional parameter vector:

EQUATION G1 — PARAMETER SPACE
$$\mathbf{p} = [p_1, p_2, \ldots, p_N]^T \qquad p_i \in [\min_i, \max_i]$$

Each pi has a range. In my run N = 15 (the UNIFIED_PARAM_NAMES list in the code, covering both families plus three strategy flags). The parameter matrix P is M × N, with M the number of winner configurations loaded.

STEP G2 — PERFORMANCE-WEIGHTED NORMALIZATION

Normalize parameters to [0, 1] and weight by performance score:

EQUATION G2 — WEIGHTED NORMALIZATION
$$\mathbf{P}_{\text{norm}} = \frac{\mathbf{P} - \mathbf{P}_{\min}}{\mathbf{P}_{\max} - \mathbf{P}_{\min}} \qquad \mathbf{P}_{\text{weighted}} = \operatorname{diag}\!\left(\sqrt{\frac{s_i}{s_{\max}}}\right)\mathbf{P}_{\text{norm}}$$

where si is the score of configuration i (profit per day in my run). The weight matrix is M × M and multiplies from the left, so it scales rows (configurations), which is what the code does. High-scoring rows pull harder on the decomposition.

STEP G3 — SVD DECOMPOSITION

Center and decompose the weighted parameter matrix:

EQUATION G3 — SINGULAR VALUE DECOMPOSITION
$$\mathbf{X} = \mathbf{P}_{\text{weighted}} - \bar{\mathbf{P}}_{\text{weighted}} = \mathbf{U}\boldsymbol{\Sigma}\mathbf{V}^T$$

Singular values σ1 ≥ σ2 ≥ … ≥ σN reveal the intrinsic dimensionality. Variance explained by dimension j:

EQUATION G4 — VARIANCE DECOMPOSITION
$$\lambda_j = \frac{\sigma_j^2}{\sum_i \sigma_i^2} \qquad d_{\text{eff}} = \min\Bigl\{d : \sum_{i \le d} \lambda_i \geq 0.95\Bigr\}$$

The 95% cutoff is the usual cumulative-variance rule (Jolliffe, Principal Component Analysis, 2nd ed., Springer 2002). Measured on my Nov 30 2025 run: deff = 2 for the trend family (95.6% in two singular values) and about 7 for the mean-reversion family.

STEP G4 — CAUSAL WEIGHT ANALYSIS

Sort parameters by how much they load on the leading components. The weight formula on the earlier version of this page was not well defined (it integrated over a dummy variable with an integrand in another, and called a singular vector an eigenfunction). What the code computes is:

EQUATION G5 — CAUSAL WEIGHTS (AS IN THE CODE)
$$w_d = \frac{\sum_{i \le K} |V_{d,i}|\,\sigma_i^2}{\sum_{d'} \sum_{i \le K} |V_{d',i}|\,\sigma_i^2}$$

where Vd,i is the loading of parameter d on the i-th right singular vector and K = 8 in the current code. So wd is the absolute loading of each parameter on the top singular vectors, weighted by variance and normalised to sum to one. High wd parameters stay free; low wd parameters get frozen. "Causal" is my label for it; it's a loading, not a causal test.

STEP G5 — FREEZING & GROUND STATE EXTRACTION

Rank parameters by causal weight, keep only the top k free, freeze the rest:

EQUATION G6 — GROUND STATE
$$p_i^* = \begin{cases}\text{free} & \text{if } w_i \geq w_{\text{threshold}} \\ \operatorname{median}_{\text{top-5\%}}(p_i) & \text{otherwise (frozen)}\end{cases}$$

Frozen values are the weighted median over the winner set, with weights si (the same score weights as G2). The "top 5%" in G6 is how I first wrote it; the code takes the weighted median over all winners it loaded, and I've left the formula so the difference is visible.

REFFELT CONSTANT AS FINGERPRINT

The singular values can be packed into a digit string, the Reffelt Constant (see Reffelt Constant). The digit encoding on this page and the one in the code differ. The code uses 8 − 10·var(k) per regime plus a separation digit. I need to pick one and delete the other. The version on this page:

EQUATION G7 — REFFELT DIGIT ENCODING (PAGE VERSION, NOT THE CODE)
$$\text{ℜ}_j = \begin{cases}9 & \lambda_j \geq 0.12 \;\text{(saturated)} \\ \lfloor 80\lambda_j \rfloor & 0.01 \leq \lambda_j < 0.12 \\ 0 & \lambda_j < 0.01 \;\text{(dead)}\end{cases}$$

Under this version a 9 means a component carrying most of the variance and a 0 means a dead one, so the string my Nov 30 run printed, ℜ = 99100000, reads as two saturated components and the rest dead. The meta-optimizer's compute_reffelt_constant does the same thing (⌊80λj⌋ clamped to [0, 8], 9 above 0.12), even though its docstring says ×10. The kernel script's version (8 − 10·var(k) for each regime, then min(8, max(1, ⌊16·separation⌋)) for the third digit) produces a different string from the same run. That's the inconsistency I have to clean up.

META-OPTIMIZER

With the ground state in hand, the search is two-dimensional. Right now the search is a plain grid: 100 values of k times two regimes. A GP-plus-Thompson version is what I want to build; it isn't written.

PLANNED: GAUSSIAN PROCESS OVER k

The plan is a GP regression from (k, regime) to score, with Expected Improvement picking the next k (Jones, Schonlau & Welch, "Efficient global optimization of expensive black-box functions", J. Global Optim. 13, 1998):

EQUATION G8 — EXPECTED IMPROVEMENT (PLANNED METHOD, NOT IMPLEMENTED)
$$\text{EI}(k) = \mathbb{E}\left[\max(f(k) - f^*, 0)\right] = (\mu(k) - f^*)\Phi(z) + \sigma(k)\phi(z)$$

where z = (μ(k) − f*) / σ(k), Φ is the normal CDF, and φ is the normal PDF.

PLANNED: THOMPSON SAMPLING OVER THE REGIME BIT

For the {0, 1} choice I'd keep a Beta posterior per regime and sample it each round (Thompson, "On the likelihood that one unknown probability exceeds another in view of the evidence of two samples", Biometrika 25, 1933). Also not written.

The grid in optimize_universal_ground_state is 100 values of k from 0.3 to 3.5 times two regimes, 200 backtests per ticker; the script's main loop runs a coarser 20 × 2 sweep from 0.5 to 2.5. Whether a GP version gets there in fewer is something I'd have to measure once it exists.

CONJECTURES I HAVEN'T TESTED

Each of these is a place the same SVD might say something. I have one measured case, in my own optimizer, and nothing beyond it.

FINE-TUNING

If this held for neural nets it would be one reason LoRA works (Hu et al., "LoRA: Low-Rank Adaptation of Large Language Models", 2021); I haven't tested that.

PRUNING

A loading-based freeze criterion might beat magnitude pruning on some nets; I haven't pruned anything with it.

HYPERPARAMETER SEARCH

The recipe (collect scored configs, SVD, freeze low loaders, search the rest) could transfer to other domains; my only run is the trading one above.

ARCHITECTURE SEARCH

If a few macro choices carried most of the variance it would rhyme with μP (Yang et al., "Tensor Programs V", 2022) and Chinchilla (Hoffmann et al., "Training Compute-Optimal Large Language Models", 2022); I haven't run the SVD on any architecture sweep.

VARIATIONAL QUANTUM CIRCUITS

Freezing low-loading rotation angles might shrink the landscape enough to matter for barren plateaus (McClean et al., "Barren plateaus in quantum neural network training landscapes", Nat. Commun. 9, 2018); that's a guess, with no circuit behind it.

HOW TO REPRODUCE

Two scripts in my repo under src/physics. universal_reffelt_meta_optimizer.py loads the optimizer's winner files, builds the 15-column parameter matrix (UNIFIED_PARAM_NAMES), applies the score weights, runs the SVD (compute_eigenstretch), prints singular values, variance explained, deff at 95%, the loadings-based weights, and the weighted-median frozen values. universal_ground_state_kernel.py is the 2D backtest: optimize_universal_ground_state sweeps k over linspace(0.3, 3.5, 100) for regime 0 and 1, and the main loop runs a 20-point sweep from 0.5 to 2.5 on BTC/USD, ETH/USD and SOL/USD 15-minute bars, then prints the best (k, regime) per ticker and the digit string. Both headers read "Anthony Reffelt + Grok 4.1, November 2025".

What isn't measured: the causal weight numbers in the freeze table, the three charts, any run outside my own optimizer, any perturbation test of the frozen values, and any GP or Thompson search.
