AMNI-CHAT · SETUP GUIDE

Run your own relay

The relay is the small server that passes your sealed messages along. Run it on any computer that stays on, and your Amni-Chat apps talk through it instead of ours. One command, about a minute, nothing to configure.

What you need

  • A computer that stays on. A spare PC, a Mac mini, a Raspberry Pi 4 or 5, or a small cloud server. The relay uses about 25 MB of memory.
  • Nothing else. No domain, no port forwarding, no certificates. Out of the box the relay gets a free https address through a Cloudflare tunnel.
  • Optional: a domain name, if you want an address that never changes. See A permanent address.

Builds: Linux (x86-64 and ARM64, any distribution), macOS (Apple silicon and Intel), Windows 10 and 11.

Install on Linux or Mac

Open a terminal and paste:

curl -fsSL https://downloads.amni-scient.com/amni-chat-relay/install.sh | sh

It asks two questions. Press Enter to skip both:

  1. Domain name. Skip it and you get a free https address. Type one in and you get your own address with a real certificate.
  2. Haven server. Paste your Haven address to let people sign in with Haven. See Sign in with Haven.

When it finishes it prints your address, for example https://quiet-river-maple.trycloudflare.com. It runs in the background and starts again after a reboot.

Run it with sudo to install for the whole machine (in /opt); without it, the relay installs for your user only.

Install on Windows

  1. Download the Windows relay and unzip it anywhere.
  2. Double-click Start Relay.bat.
  3. Press Enter twice to skip the questions.

The window shows your address and a QR code. Keep the window open while you want the relay running; close it to stop.

Windows may ask whether to let amni-chat-server use the network. Click Allow. Calls and devices on your home network need it.

Install with Docker

Works with Docker or Podman. Use arm64 instead of amd64 on a Raspberry Pi.

curl -fsSL https://downloads.amni-scient.com/amni-chat-relay/amni-chat-relay-docker-amd64.tar.gz \
  | docker load
docker run -d --name amni-chat-relay --restart unless-stopped \
  -v amni_chat:/data -e AMNI_CHAT_TUNNEL=cloudflare amni-chat-relay

Then docker logs amni-chat-relay shows your address and QR code. Everything the relay keeps lives in the amni_chat volume.

With your own domain instead of the tunnel:

docker run -d --name amni-chat-relay --restart unless-stopped \
  -v amni_chat:/data -p 80:80 -p 443:443 \
  -e AMNI_CHAT_DOMAIN=chat.example.com amni-chat-relay

Connect your apps

Android

Settings › Advanced › Relay server. Paste your address. When creating an account, tap Change server first.

iPhone

Settings › Relay. Paste your address. When creating an account, open Advanced first.

Web

Open your relay’s address in a browser. The web app is built in, and it already talks to your relay.

Everyone you chat with needs to be on the same relay. Send them your address.

A permanent address

The free tunnel address changes whenever the relay restarts, and the apps then need the new one. For an address that stays put, use a domain:

  1. Point a domain or subdomain at your computer’s public IP address with an A record, for example chat.example.com.
  2. Forward TCP ports 80 and 443 on your router to that computer. A cloud server usually has them open already.
  3. Run the installer again and type the domain when asked, or edit AMNI_CHAT_DOMAIN in relay.env and restart.

The relay gets and renews its own Let’s Encrypt certificate. There’s no separate web server or certbot to run.

Already use Cloudflare? A named Cloudflare Tunnel pointing at http://localhost:8991 also gives a fixed address without opening ports.

Sign in with Haven

Run a Haven server? Your members can sign in to Amni-Chat with their Haven account and find each other by Haven name.

  1. Give the relay your Haven address: answer the installer’s second question, or set AMNI_CHAT_HAVEN_URL=https://haven.example.com in relay.env.
  2. To make the relay members-only, set AMNI_CHAT_HAVEN_ONLY=1. Then only people who sign in with that Haven server can create an account or send messages.
  3. To allow only certain members, list them: AMNI_CHAT_HAVEN_USERS=alice,bob.

In the apps, Sign in with Haven appears when creating an account and in Settings. It opens Haven, the person taps Approve, and they come back signed in. Friends can then search for @theirname.

Haven tells the relay who signed in, and the relay keeps only the username. Haven never sees Amni-Chat messages, and the relay never sees Haven passwords.

Calls

Most calls connect phone to phone. When a network blocks that, the call goes through a TURN server, and the relay starts its own.

The built-in TURN server needs UDP port 3478 and UDP ports 49160–49200 to reach your computer. It opens them on your router automatically when the router supports UPnP; otherwise, forward them by hand. Without them, calls still work on most networks and fall back to public TURN servers on the rest.

Notifications

  • Web app: works out of the box. The relay makes its own Web Push keys.
  • Android without Google: install a UnifiedPush distributor such as ntfy, then turn on Settings › Notifications › Google-free push.
  • Android and iPhone through Google and Apple: optional. Set AMNI_CHAT_FCM_SA to a Firebase service-account file you own.

An open app always gets messages instantly over its live connection, with no push service at all.

Update, back up, remove

Update

Run the install command again, or download the new Windows zip over the old folder. Your data and settings stay.

Back up

Copy the data folder. It holds the database and the relay’s keys. Restore it to move the relay to another computer.

Remove

The installer prints the exact commands. On Windows, close the window and delete the folder.

All settings

Put these in relay.env, or pass them with -e to Docker, then restart. None are required.

Troubleshooting

The app says it can’t reach the relay.
Open the address in a browser. If the web app loads, check that the app has exactly that address, starting with https://. If it doesn’t load, check the logs.
The address stopped working after a restart.
That’s the free tunnel: it gets a new address each time. Look in data/public-url.txt for the new one, or set up a permanent address.
No certificate for my domain.
Ports 80 and 443 must reach this computer, and the domain’s A record must point at its public IP. The logs say what Let’s Encrypt answered.
Calls connect but there’s no audio or video.
The call needed TURN and couldn’t reach it. Forward UDP 3478 and 49160–49200, or set AMNI_CHAT_TURN_PUBLIC_IP.
Sign in with Haven never finishes.
The person must already be logged in to Haven in that browser. Approvals expire after a minute; start again from the app.

What the relay can see

Messages are encrypted on the phone before they reach the relay, with keys that rotate weekly. The relay stores sealed messages until they’re delivered, public keys, hashed phone numbers and emails, Haven names of people who signed in with Haven, and timestamps. It sees when a device connects and from which IP address, and keeps that only in memory. It can’t read messages, calls or attachments. More on the relay page.
