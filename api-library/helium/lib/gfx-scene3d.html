gfx/scene3d

A 3D renderer for glTF assets with sun shadows, ambient occlusion, temporal upscaling, bloom and color grading.

import gfx.scene3d; · s3d:: · 166 functions, 47 types, 365 constants · Source

Notes from the source
scene3d: a forward renderer for glTF assets loaded by gfx.gltf.

Frame structure (render):
  1. deformation data: joint matrices for every skinned instance, one storage buffer
  2. sun shadows: CASCADES depth layers fitted to slices of the view frustum
  3. prepass (one sample per pixel, no MSAA): view normal + depth for SSAO and,
     when temporal runs (or `motion_vectors` is set), a second target, `motion`:
     every pixel's screen motion since last frame (uv units, from unjittered
     clip positions, skinning included), its view depth now and the same
     surface point's view depth last frame. One sample per pixel means a
     silhouette pixel holds the motion and depth of one surface (the one under
     its sample point), never an MSAA average of two. Then hemisphere SSAO and
     a depth-aware blur when SSAO is on.
  4. colour: 4x MSAA RGBA16F; sky, opaque and cut-out surfaces, blended
     surfaces far to near, then particles (gfx.sparks); resolved to `hdr`.
  4b. temporal (when `temporal` is on, or the output is larger than the render
     size): jittered frames accumulate into a history image at the output size
     (shaders/temporal.frag); TAA at equal sizes, a temporal upscaler otherwise
  5. bloom: threshold, a chain of half-size reductions, tent expansion back up
  6. grading: exposure, curve and sRGB into the caller's RGBA8 target

The scene is plain data: `view`, `sun`, `sky`, `look`, `lights` and `items` are
globals the caller edits between frames. Each frame the item list is flattened
into `batch` (one Batch per primitive draw, with its matrices and sort depth),
so later stages such as GPU culling or a velocity pass can consume the same
list. prev_* fields are kept for motion vectors.
