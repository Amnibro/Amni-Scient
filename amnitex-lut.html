WHY LONG AI SESSIONS HIT A WALL

THE O(N²) HISTORY TRAP & LOSSY COMPACTION

When you use an LLM for a long coding session, two things eat your context window: file discovery (grepping and reading whole files) and the conversation history itself.

Most clients resend the whole conversation on every turn: Turn 1 is copied into Turn 2, Turns 1–2 into Turn 3, and so on. Across N turns, cumulative input scales as N(N+1)/2 = O(N²). Prompt caching makes the repeated part cheaper, but it still fills the window.

When the window fills up, clients run summary compaction: older turns are summarized into a smaller block. Summaries can drop exact constants, port numbers and struct fields from earlier turns. How much they drop depends on the summarizer; we have not yet measured a real one.

THE IDEA: START FRESH EVERY TURN FROM AMNITEX

Look-up tables (LUTs) don’t re-read their whole table on every query. AmniTex (atex) treats both your codebase and your conversation history as an external byte-page LUT.

After each turn, a native Gold / Helium lifecycle hook writes the full, unedited turn into a 1 MB binary page (conv::<id>::turn_N) and updates a small state card (conv::<id>::state). Every word and snake_case subword is hashed into a 2D spatial TexGrid. This part works today.

The goal is a client that sends only the system prompt, tool schemas, the state card, a few recalled snippets and the new prompt, instead of the full history. Per-turn input would then stay roughly flat. No client does this yet, so the fresh-turn numbers on this page are projections, not measurements.

HOW THE 2D SPATIAL TEXGRID WORKS

01 — BINARY BYTE PAGES

1 MB .kb.page Containers

Every repo doc, code chunk, and conversation turn (conv::<id>::turn_N) is appended raw and unedited into 1 MB page files (4096 × 64 × 4 bytes). No vector embeddings, no external database, and no lossy summarization.

02 — COMPOUND + SUBWORD HASHING

2D Spatial Coordinate LUT

Each identifier and its _ / - / . subwords are hashed with 64-bit FNV-1a into (x, y) coordinates on a W × H grid. Each cell holds 4 inline document IDs in a flat contiguous array plus an overflow chain.

03 — STATELESS TURN COMPACTION

Fresh Context Window Every Turn

At the end of every turn, context_tracker_bin writes the turn to .atex and updates conv::latest_state (~210 tokens). Any turn—or a brand-new session—recalls exact prior turns in 1.66 µs without re-reading the conversation.
