UNDERSTANDING FILE ENCRYPTION

File encryption transforms readable data into ciphertext using a mathematical algorithm and a secret key.

Why file-level encryption matters: Full-disk encryption protects data at rest when a device is powered off, but it doesn't help if an attacker gains access while the system is running.

The algorithm is only half the story. Key derivation, turning your passphrase into that secret key, is equally critical.

The Shadow Protocol in Amni-Crypt adds an additional layer: a shadow stream that runs through every round beside your data, and a key-dependent walk every passphrase guess has to take.

SHADOW PROTOCOL

A dual-stream design: your data and a shadow stream co-evolve through identical transformations, for a doubly-wide effective state space.

16 ROUNDS

SubBytes + MixColumns (T-table fusion), key-driven row shuffles and rotations, then row and column MDS mixing. Every round processes both streams in lockstep.

HOW IT WORKS

1. KEY DERIVATION

Your passphrase is stretched through Argon2id (256 MiB, 3 passes) with a random salt, then a 64 MiB shadow-stretch walk. That unlocks a random 256-bit file key, and every other key is derived from it.

2. SHADOW SEEDING

SHAKE-256 generates the shadow stream from (key || chunk number): a deterministic pseudorandom stream unique to every chunk of every encryption.

3. 16-ROUND SPN

Each round runs T-table fusion (SubBytes + MixColumns), a key-driven row shuffle and rotation, and row and column MDS mixing. The shadow XORs into the data before substitution, creating an entangled state.

4. CONTAINER SEAL

Each encrypted chunk is sealed with ChaCha20-Poly1305 and packaged in the V4 binary format with salt, nonce, key slots, header MAC and metadata. Out comes a .acrypt file. Older V1–V3 and AMNILOCL containers still decrypt.
