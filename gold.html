How we measured, and where Helium loses

Same answers: every input was run through the original program and the rewrite, and their output compared line by line. 3,235 lines match byte for byte. The other 30 are inputs both versions reject as invalid, where the error message is worded differently (Rust's JSON reader and Python's regex library phrase errors their own way).

Tokens: counted with Claude's own tokenizer, original source files against the Gold files. The Helium that Gold writes from them is 143,805 tokens; you read and edit the Gold, not the Helium. Gold is longer than the original only for the CAD unit code, which is 34 dense lines of JavaScript. The first rewrites saved 24%. Three Gold additions took that to 50%: a one-line header that says which language the code came from (so its number and rounding rules are never spelled out again), data tables packed with column units and blank-means-same-as-above cells, and a shortening pass that rebuilds the program from the shorter Gold and keeps it only if every test input still gives the same answer and it runs no more than 15% slower.

Speed: each program runs the same inputs many times in one process; we report the fastest of 5 runs, start-up included, on a shared Linux desktop. Helium is still slower than Rust on Amni-Calc, mostly in turning numbers into text, where Rust's newest formatter takes about a fifth of the time per number. Amni-Crypt also ships a hand-tuned C version of the same layer that uses special vector instructions for its math; that runs 13× faster than the Helium rewrite.

Fixes along the way: the rewrites found 21 gaps in Helium itself: missing math and number-format functions, a regex crash, four unsafe code patterns the compiler now rejects, memory from short-lived values not being given back (Amni-Calc used 601 MB, now 5 MB), loops copying each item instead of reading it in place, and slow paths in regex, JSON, number printing, sorting short lists, clearing memory and atan2. All are fixed in Helium.
