WHAT IT IS

Gold is plain English that compiles to Helium, our compiled language. You describe what a program or a product feature does, one short block at a time. Gold finds the functions your product already has, has an AI model write the Helium, checks it with the Helium compiler (types, memory safety, and the exact output when you give one), fixes compile errors on its own, and saves the result so the same Gold always builds the same program.

IN THE TERMINAL

$ gold build units.gold gold: translating 6 of 6 blocks with sonnet gold: repairing 1 block(s), round 1 gold: units.amni ok (6 blocks, 294 Gold words -> 846 Helium words; 2 model calls, $0.19, 36 s) $ gold run units.gold $ gold test units.gold
StepWhat you do
1. Headeruse the product (or Helium library modules) whose functions the code should call, into the file to write, and optionally dialect js (or rust, python, java, kotlin, numpy) when you port code, so that language's number and rounding rules apply everywhere without being spelled out.
2. BlocksOne block per unit, separated by blank lines. Say what it does: inputs, result, rules, formats, edge cases. Put exact names in backticks only when other code calls them.
3. Buildgold build f.gold writes checked Helium. Edit one block and rebuild: only that block goes back to the model.
4. Checkgold run, gold test, or an expect: list of exact output lines that Gold runs and repairs against.
5. Portgold port app.rs into=src/app.he reads existing code in any language and writes the Gold for it, then builds it.
6. Shrinkgold compact packs data tables; gold squeeze f.gold check='<cmd>' shortens the Gold and keeps the shorter version only if a fresh rebuild still passes your check.

How we measured, and where Helium still loses

Same answers: every input was run through the original program and the rewrite, and their output compared line by line. 3,235 lines match byte for byte. The other 30 are inputs both versions reject as invalid, where the error message is worded differently (Rust's JSON reader and Python's regex library phrase errors their own way).

Tokens: counted with Claude's own tokenizer, original source files against the Gold files. The Helium that Gold writes from them is 140,139 tokens; you read and edit the Gold, not the Helium.

Speed: each program runs the same inputs many times in one process; we report the fastest of several runs, start-up included, on a shared Linux desktop (AMD Ryzen 9 9950X3D). Amni-Calc is the one rewrite still slower than its original, by 1.10×, mostly in turning numbers into text. Helium now finds a number's shortest digits with one wide multiply instead of three (the method Rust's newest formatter uses), but the rest of its number printing still runs more instructions than Rust's. Amni-Crypt also ships a hand-tuned C version of the same cipher layer built on the CPU's AES and GFNI vector instructions; the Helium rewrite now uses those same instructions through its new gf library and is now only 1.07× slower than it (it was 13× slower).

Fixes along the way: the rewrites found gaps in Helium itself, all now fixed: missing math and number-format functions, a regex crash, four unsafe code patterns the compiler now rejects, memory from short-lived values not being given back (Amni-Calc used 601 MB, now 5 MB), loops copying each item instead of reading it in place, slow paths in regex, JSON, number printing, sorting short lists, clearing memory, string escaping, splitting words and atan2, a buffer resize that zero-filled one byte at a time, and no access to the CPU's AES and GFNI instructions.
